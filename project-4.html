KINPO SRM-ERP Order Integration Platform

Problem

Purchase orders and order-change notifications between Kinpo's Supplier Open API and Sercomm's internal SRM/ERP systems were not integrated, requiring manual review and entry. This created delays in responding to order changes, increased the risk of missed deadlines within supplier change windows, and made it difficult to evaluate order feasibility against production capacity in a timely way.

Solution

I built a full-stack order integration platform connecting Kinpo's Supplier Open API with Sercomm's internal SRM and ERP systems. The platform ingests inbound purchase orders and order-change (POC) notifications via signed API calls, then applies business rules — including a 70-day change window and APS-based feasibility evaluation — to automatically generate accept, change, or reject responses. Approved orders are synced into Oracle ERP through PL/SQL MERGE/INSERT pipelines with per-record commit and retry logic to ensure reliability. The system runs on FastAPI with Celery/Redis for asynchronous task orchestration, APScheduler for weekly APS snapshot jobs, and maintains dual-database persistence — SQL Server for SRM data and Oracle for ERP data — with automated error tracking, email alerting, and a Vue 3 admin dashboard for order and log visibility.

Tech Stack

  • Python & FastAPI
  • Celery & Redis (async task orchestration)
  • APScheduler (scheduled APS snapshot jobs)
  • SQL Server (SRM data) & Oracle (ERP data, PL/SQL MERGE/INSERT)
  • REST API Integration (signed API calls)
  • Vue 3 (admin dashboard)
  • Automated error tracking & email alerting

Your Role

I served as both project lead and lead developer, designing the system architecture end to end — from API integration and business rule design to the database synchronization strategy and admin dashboard. I worked closely with supply chain and ERP stakeholders to define the acceptance rules and feasibility logic embedded in the platform.

Impact / Metrics

  • Automated response generation for inbound purchase orders and order changes
  • Reduced manual review effort through rule-based accept/change/reject logic
  • Improved reliability of ERP synchronization with per-record commit and retry handling
