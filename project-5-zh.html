HCL Notes 至 SQL Server 的 BPM 資料遷移與同步平台

問題

超過 300 個 BPM 表單、累積了多年的歷史業務資料，存放在 HCL Notes 12 這套 報表與整合能力有限的既有平台上。若以人工方式將這麼大量的表單 — 每個表單 皆有不同的欄位結構、雙語標籤與主從（Master/Detail）關聯 — 遷移至現代化資料庫， 勢必極為耗時且容易出錯，而業務單位也需要在轉換期間讓新舊系統保持同步。

解決方案

我建構了一套端到端的資料遷移與同步平台，透過 Domino REST API（DRAPI） 自動化 300 多個 BPM 表單從 HCL Notes 12 遷移至 SQL Server 的歷史資料遷移作業。 平台運用 Claude AI API 進行語意推論以判斷欄位對應關係 — 協調中英文標籤、 資料型別與主從結構的差異 — 並在資料實際搬移前自動產出 Excel 對應表供業務審核。 對應表確認後，系統會自動在 SQL Server 建立目標資料表，並執行完整歷史資料匯入。 為了讓兩套系統在轉換期間持續保持一致，我也建置了持續性的增量同步機制， 包含未讀文件檢查點（unread-document checkpointing）、依 notes_unid 執行 新增／更新的 SQL Server UPSERT 邏輯、軟刪除（soft-delete）處理， 以及具備失敗 Email 警示的同步稽核紀錄。

技術棧

  • Python
  • Domino REST API (DRAPI)
  • Claude AI API（語意欄位對應推論）
  • SQL Server（UPSERT 式同步、軟刪除處理）
  • 歷史與增量資料遷移的 ETL 管線
  • 自動化稽核紀錄與 Email 警示

我的角色

我設計並建構了整套遷移與同步平台，包含 AI 輔助欄位對應流程與增量同步架構。 我也與這 300 多個表單各自的業務負責人協調，於遷移前逐一審核並確認 AI 產出的對應表。

成效／指標

  • 自動完成 300 多個 BPM 表單的遷移，無需人工進行欄位對應
  • 在轉換期間實現 HCL Notes 與 SQL Server 之間持續且可靠的同步
  • 透過檢查點機制、軟刪除處理與稽核紀錄降低資料遺失風險
